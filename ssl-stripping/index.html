SSL Stripping

Gembok yang dicopot
Intinya

Penyerang yang berada di tengah jalur berbicara HTTPS dengan server asli, tetapi menyajikan HTTP polos ke korban, sehingga kata sandi korban terbaca. Penangkal utamanya adalah header HSTS [1].

01

Definisi

SSL Stripping adalah serangan Man-in-the-Middle yang menurunkan koneksi korban dari HTTPS menjadi HTTP polos, tanpa memecahkan enkripsinya.

HTTP adalah bahasa browser dan web server yang mengirim data sebagai teks polos. HTTPS adalah HTTP yang dibungkus enkripsi TLS (nama lamanya SSL), ditandai ikon gembok [2]. MitM (Man-in-the-Middle) adalah posisi penyerang yang diam-diam berada di tengah jalur komunikasi [2]. Anatomi SSL Stripping terdiri dari empat bagian [1]:

Intersepsi HTTP initial

Mencegat permintaan HTTP sebelum dialihkan ke HTTPS.

Dual-connection proxy

HTTPS ke server asli, tetapi HTTP polos ke browser korban.

Pencurian kredensial

Membaca formulir login yang dikirim lewat HTTP yang sudah diturunkan.

Proteksi HSTS header

Memaksa browser menolak koneksi HTTP polos secara permanen.

02

Tujuan mempelajari

  • Memahami bahwa enkripsi kuat bisa dikalahkan tanpa dipecahkan, cukup dengan mencegahnya dimulai.
  • Mengenali tanda-tanda di layar: alamat http://, gembok hilang, dan tulisan "Tidak aman".
  • Menerapkan pertahanan di sisi server (HSTS, atribut cookie) dan di sisi pengguna (VPN, kebiasaan memeriksa gembok).
  • Memahami batas HSTS, terutama celah kunjungan pertama dan cara menutupnya dengan preload.
03

Relevansi keamanan siber

SSL Stripping menyerang kerahasiaan (confidentiality): kata sandi dan cookie sesi jatuh ke tangan penyerang. Token sesi adalah "kunci emas": siapa yang memegangnya bisa masuk tanpa password, bahkan melewati MFA [1]. Wi-Fi publik membuat serangan ini realistis, karena pengguna bisa saling berkomunikasi, sinyal tidak terenkripsi bisa ditangkap, dan hotspot palsu (Evil Twin) mudah dibuat [2].

04

Etika

Simulator ini hanya model visual dengan domain fiktif (bank.contoh) dan kredensial palsu. Situs ini tidak memuat alat atau perintah serangan. Teknik MitM hanya boleh dipelajari di lab yang diizinkan [3]; menyadap atau mengakses sistem orang lain tanpa hak adalah tindak pidana menurut UU ITE [10][11].

Yang perlu diingat

  1. SSL Stripping menurunkan HTTPS menjadi HTTP polos tanpa memecahkan enkripsi.
  2. Empat bagian: intersepsi HTTP awal, proxy dua koneksi, pencurian kredensial, proteksi HSTS.
  3. Yang diserang adalah kerahasiaan: password dan cookie sesi.

Mengapa HTTPS bisa dilepas

Intinya

HTTPS melindungi data yang lewat, tetapi tidak melindungi momen sebelum HTTPS dimulai. Penyerang yang sudah berada di tengah memanfaatkan momen itu.

  1. Apa yang dilindungi TLS
  2. Celah permintaan pertama

  4. Contoh kasus: Wi-Fi publik

01

Apa yang dilindungi TLS

Protokol lama seperti HTTP (port 80), Telnet, FTP, dan POP3 mengirim data sebagai teks polos, sehingga form login, cookie sesi, dan kata sandi bisa disadap [2]. TLS bekerja di atas TCP: kriptografi asimetris (RSA/ECC) dipakai untuk bertukar kunci, lalu kriptografi simetris (AES-GCM) dipakai untuk mengenkripsi data [2][9]. Penyadap hanya melihat data acak.

Karena itu, penyadapan lewat ARP poisoning menjadi tidak berguna terhadap HTTPS [2]. SSL Stripping adalah cara mengakali hal itu: bukan dengan memecahkan enkripsi, tetapi dengan mencegahnya dimulai.

02

Celah permintaan pertama

Kebanyakan orang mengetik bank.contoh, bukan https://bank.contoh. Browser yang belum punya aturan khusus lalu mengirim permintaan pertama lewat HTTP polos, dan server menjawab "silakan pindah ke HTTPS". Jawaban pengalihan itu masih lewat HTTP, dan di situlah penyerang mencegat [1][5].

Tanpa penyerang

Browser mengirim http://bank.contoh, server membalas "pindah ke https://", browser lalu membuka koneksi TLS. Selamat, karena tidak ada yang mencegat pengalihan.

Dengan penyerang di tengah

Penyerang menangkap permintaan HTTP itu, membuka HTTPS sendiri ke server, lalu terus melayani korban lewat HTTP. Korban tidak pernah "naik" ke HTTPS.

03

Cara masuk ke tengah

SSL Stripping hanya bisa dilakukan jika penyerang sudah berada di jalur. Komponen dan teknik yang terlibat:

ARP poisoning

ARP tidak punya otentikasi. Penyerang mengirim balasan ARP palsu ke korban dan router, lalu menyalakan IP forwarding agar koneksi korban tetap berjalan dan ia tidak curiga [2].

Evil Twin

Hotspot Wi-Fi palsu dengan nama mirip hotspot asli, sehingga semua trafik korban melewati perangkat penyerang [2].

DNS spoofing

Penyerang menjawab pertanyaan DNS korban lebih cepat dari server asli, sehingga nama domain diarahkan ke alamatnya [1].

Rogue DHCP

Server DHCP palsu memberi korban gateway dan DNS milik penyerang [2].

Situs ini sengaja tidak menampilkan perintah atau alat untuk melakukan teknik-teknik tersebut.

04

Contoh kasus: Wi-Fi publik

Seseorang di bandara atau kafe tersambung ke Wi-Fi gratis, tanpa tahu bahwa hotspot itu palsu.

Dokumentasi MDN memakai skenario serupa: pengguna di bandara tersambung ke rogue access point, sehingga koneksi HTTP-nya bisa dibelokkan; HSTS membuat browser menolak penurunan itu [6]. Materi kuliah mencatat kerentanan hotspot terbuka: tidak ada isolasi antarpengguna, paket Wi-Fi bisa ditangkap, dan Evil Twin dengan SSID serupa. Rekomendasinya: selalu VPN, paksa HTTPS/HSTS, dan matikan sambung otomatis [2].

Coba di simulator. Skenario "Wi-Fi kafe, Evil Twin" memperagakan kasus ini dengan domain fiktif bank.contoh.

Komponen 3 · Proses Bertahap

Dari Wi-Fi palsu sampai password terbaca

Intinya

Penyerang masuk ke tengah, mencegat permintaan HTTP pertama, membuka dua koneksi berbeda, lalu membaca formulir login. HSTS memotong rantai ini di langkah kedua.

6 tahapdari posisi MitM sampai penyamaran sempurna
01

Tahap demi tahap

  1. Masuk ke tengah.Penyerang menjadi perantara lewat Evil Twin, ARP poisoning, DNS spoofing, atau rogue DHCP [1][2].
  2. Intersepsi HTTP awal.Korban mengetik bank.contoh. Permintaan HTTP pertama ditangkap sebelum server sempat mengalihkan ke HTTPS [1].
  3. Proxy dua koneksi, sisi server.Penyerang membuka HTTPS yang sah ke server asli. Di mata server, ini pengunjung biasa [1].
  4. Proxy dua koneksi, sisi korban.Penyerang mengganti semua tautan https:// menjadi http:// dan melayani korban lewat HTTP polos [1].
  5. Pencurian kredensial.Korban mengisi formulir login; penyerang membacanya sebagai teks polos [1].
  6. Penyamaran sempurna.Penyerang meneruskan login ke server lewat HTTPS. Korban masuk ke akunnya seperti biasa, dan penyerang juga memegang cookie sesinya [1].

Di mana HSTS memotong rantai

Jika browser sudah mengenal aturan HSTS situs itu, alamat http:// diubah menjadi https:// di dalam browser, sebelum ada paket yang keluar. Tahap 2 tidak pernah terjadi, dan jika penyerang menyodorkan sertifikat palsu, browser menolak tanpa memberi pilihan "lanjutkan" [4][5][6].

02

Sisi pembela: deteksi

  • Di komputer korban: jika dua alamat IP berbeda (misalnya gateway dan komputer lain) memiliki MAC address yang sama di tabel ARP, hampir pasti terjadi ARP poisoning [2].
  • Di jaringan: gelombang balasan ARP yang dikirim tanpa diminta, dan lonjakan balasan ARP lebih dari 100 per detik per host, adalah indikator SOC [2].
  • Di aplikasi: perubahan alamat IP atau User-Agent secara tiba-tiba di tengah sesi dengan cookie yang sama patut dicurigai [1].
  • Di layar: gembok hilang dan alamat diawali http:// di halaman yang biasanya aman.

Yang perlu diingat

  1. Masuk ke tengah, cegat HTTP awal, proxy dua koneksi, baca login, teruskan ke server.
  2. HSTS memotong rantai sebelum paket HTTP pertama keluar.
  3. ARP duplikat dan gembok yang hilang adalah tanda bahaya.

    Menjaga gembok tetap terpasang

    Intinya

    Server memasang HSTS dan mendaftar ke preload list, cookie diberi atribut pengaman, dan pengguna memakai VPN di Wi-Fi publik serta memeriksa gembok.

    1. HSTS
    2. Atribut cookie

    01

    HSTS

    HTTP Strict Transport Security (RFC 6797) adalah instruksi dari server agar browser hanya berkomunikasi lewat HTTPS dengan situs itu selama jangka waktu tertentu [1][4]. Browser otomatis menolak HTTP polos sebelum dikirim ke jaringan, dan tidak membiarkan pengguna melewati peringatan sertifikat yang tidak valid [5][6].

    Nginx / Apache · header HSTS
    add_header Strict-Transport-Security
    Tambahkan header Strict-Transport-Security pada setiap jawaban HTTPS [1].
      "max-age=31536000;
    Ingat aturan selama 31.536.000 detik = 365 hari [6].
       includeSubDomains"
    Berlaku juga untuk semua subdomain, misalnya login.bank.contoh [4].
      always;
    Kirim header pada semua jenis jawaban, termasuk halaman error.

    Preload. Domain yang memenuhi syarat (sertifikat valid, pengalihan HTTP ke HTTPS, semua subdomain HTTPS, max-age minimal 31536000, includeSubDomains, dan preload) bisa didaftarkan ke daftar yang tertanam di browser, sehingga terlindungi bahkan sebelum kunjungan pertama [8]. Keputusan ini sulit dibatalkan, jadi pastikan semua subdomain sudah siap HTTPS [5][8].

    02

    Atribut cookie

    Cookie sesi adalah "gelang tiket" setelah login. Atribut pengaman memperkecil cara tiket itu dicuri [1][7]:

    Header Set-Cookie yang ideal
    Set-Cookie: PHPSESSID=xyz123abc987;
  Path=/;
    Nama dan nilai cookie sesi; berlaku di seluruh situs.
      Secure;
    Hanya dikirim lewat https:. Cookie yang sudah tersimpan tidak ikut terkirim di koneksi HTTP yang di-strip [7].
      HttpOnly;
    JavaScript tidak bisa membacanya lewat document.cookie; menangkal XSS [7].
      SameSite=Strict
    Hanya dikirim untuk permintaan dari situs yang sama; menangkal CSRF [7].

    Catatan penting. Atribut cookie tidak mencegah password dicuri saat SSL Stripping, karena korban mengetik password di halaman HTTP palsu. Atribut ini melindungi cookie lama dan menutup celah lain (XSS, CSRF). Penangkal utama SSL Stripping tetap HSTS.

    03

    Praktik pengguna

    Selalu VPN di Wi-Fi publik

    Seluruh trafik dibungkus terowongan terenkripsi (WireGuard/OpenVPN), sehingga penyerang di jaringan lokal tidak bisa menyentuh HTTP Anda [1][2].

    Paksa HTTPS

    Ketik https://, gunakan bookmark, atau nyalakan mode HTTPS-only di browser [2].

    Periksa gembok

    Halaman login tanpa gembok, atau dengan tulisan "Tidak aman", berarti berhenti.

    Matikan sambung otomatis

    Jangan biarkan perangkat bergabung sendiri ke hotspot terbuka, karena itulah pintu masuk Evil Twin [2].

    Di sisi jaringan, Dynamic ARP Inspection, DHCP Snooping, dan Port Security mencegah penyerang masuk ke tengah sejak awal [2].

    04

    Batasan HSTS

    HSTS baru bekerja setelah browser pernah membuat satu koneksi aman ke situs itu.

    Browser mengabaikan header HSTS yang dikirim lewat HTTP, agar tidak bisa dipalsukan penyerang [6]. Akibatnya, kunjungan pertama, atau kunjungan setelah max-age habis, masih bisa dicegat; RFC 6797 menyebutnya bootstrap MITM vulnerability [4]. Celah ini ditutup oleh HSTS preload list [6][8]. HSTS juga hanya melindungi situs yang memasangnya.

    Yang perlu diingat

    1. HSTS (max-age=31536000; includeSubDomains) membuat browser menolak HTTP polos.
    2. Preload menutup celah kunjungan pertama.
    3. Cookie Secure, HttpOnly, SameSite=Strict melindungi cookie, tetapi tidak menggantikan HSTS.
    4. VPN dan kebiasaan memeriksa gembok melindungi pengguna di Wi-Fi publik.
